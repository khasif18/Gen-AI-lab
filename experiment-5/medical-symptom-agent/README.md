# AI Medical Symptom Checker

## Experiment
**AI Agent with Reasoning Capability Using Knowledge Representation and Rule-Based Decision Making**

This is Experiment 3 for a B.Tech AI/ML laboratory. It is a browser-only educational simulation. It uses no machine learning, deep learning, LLM, external medical API, real patient data, or backend database.

## Problem statement
Develop a medical symptom checker in which an AI agent accepts selected symptoms as facts and uses a small, fictional knowledge base plus predefined rules to display possible condition patterns and an explainable reasoning trace.

## Features
- Structured `knowledgeBase` and separate `rules` collection in `knowledge-base.js`.
- `SymptomEnvironment` and `MedicalReasoningAgent` JavaScript classes.
- Forward-chaining-style rule evaluation with a transparent `matched / required * 100` rule-match score.
- Visible Perception -> Fact creation -> Rule evaluation -> Inference timeline.
- Ranked result cards and a Chart.js rule-match bar chart.
- Flu, cold, migraine, allergy, stomach, and no-match built-in examples.
- Responsive healthcare laboratory dashboard UI.

## How to run
Open `index.html` directly in a browser. The Chart.js visualization is loaded from a CDN when internet access is available; all core reasoning still works without the chart library.

For a local server, run from this directory:

```powershell
python -m http.server 8000
```

Then visit `http://localhost:8000`.

## Knowledge representation
Facts are selected symptom identifiers such as `fever`, `cough`, and `fatigue`. Rules are readable objects with an ID, condition, required symptoms, conclusion, and explanation.

```javascript
{
  id: "R2",
  condition: "Influenza",
  requiredSymptoms: ["fever", "cough", "body_ache", "fatigue", "headache"],
  conclusion: "Possible Influenza pattern"
}
```

## Reasoning algorithm
1. The environment receives selected symptoms.
2. `perceive()` records the input and `createFacts()` stores symptoms as facts.
3. Every rule is checked against those facts.
4. The engine counts matched symptoms and calculates `matched / required * 100`.
5. Results at or above the 40% demonstration threshold are stored.
6. Results are sorted by rule-match score and displayed with matched facts and rule IDs.

The score is only a demonstration of overlap with predefined rules. It is not a probability, medical confidence score, or diagnosis.

## Example inputs
- Flu: Fever, cough, body ache, fatigue, headache.
- Cold: Runny nose, sneezing, sore throat, mild cough.
- Migraine: Headache, nausea, sensitivity to light.
- No match: Fever and itchy eyes.

## Safety limitation
All conditions, symptoms, and rules are fictional demonstration knowledge for a college practical. The application must not be used for real medical decisions, diagnosis, or treatment. Real symptoms require a qualified healthcare professional.
